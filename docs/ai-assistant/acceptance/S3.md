# 第 3 階段驗收報告：對話內互動選項與補填介面

- 狀態：**自測通過，待複驗**（Codex）。
- 日期：2026-10-30。分支 `p0-baseline-hardening`，未 commit。測試資料：第 0 階段固定資料（A、B、限制專案 X 僅 B 為成員）。

## 1. A2UI 評估與決定

| 面向 | A2UI（Agent-to-UI，宣告式 UI 協定） | 現有結構化卡片（沿用並擴充） |
|---|---|---|
| 誰決定畫面 | 模型產生元件樹（從受信任元件目錄中選），前端渲染 | 模型只呼叫工具並指定「哪些欄位」；卡片內容（欄位型別、選項、版本）由**後端依表單規格產生** |
| 安全 | 不執行任意程式碼，但版面與內容由模型組成，仍需逐元件驗證 | 白名單 kind＋伺服器端 `sanitizeBlocks`；選項值、人員清單、專案搜尋都來自 DB 與權限查詢 |
| 動作路徑 | 使用者動作回傳給代理（模型）再決定做什麼 | 按鈕直接呼叫型別化的 server action，**與自然語言共用 `fillDraft`／`createDraftWithFill`**；不經模型，結果確定 |
| 版本與冪等 | 協定本身不處理業務版本 | 卡片綁定草稿版本；卡片在 DB 中原子鎖定，連點或重送只執行一次 |
| 整合成本 | 需引入渲染器與元件目錄、把每個動作再映射到現有服務、重寫已存的訊息格式 | 沿用已存的 `ai_messages.blocks`、既有前端元件與權限 |

**決定**：沿用現有結構化卡片。理由：本系統的關鍵需求（只寫合法值、版本檢查、權限、連點不重複、與文字操作同一服務）都在後端，卡片只是後端狀態的投影；A2UI 讓模型組畫面的彈性在這裡沒有必要，還會增加一層「模型決定動作」的不確定性。現有卡片格式本身就是宣告式、目錄式（白名單 kind），日後若要對外提供 A2UI，可在輸出端把卡片轉成 A2UI surface，不需改業務路徑。這不是以「框架未整合」為由延後功能——所有必要元件都已接上真實資料（第 3 節）。

## 2. 修改摘要

| 根因（實測重現） | 修正 | 檔案 |
|---|---|---|
| 點選答案只存在畫面上，重新整理後選項又可以再點 | 卡片狀態（open／answered／expired）與結果存回 `ai_messages.blocks`；動作前以交易鎖定該訊息，只有 open 能進入處理，連點或重送只執行一次 | `src/lib/ai-chat/block-actions.ts`（新） |
| 專案卡直接寫 DB，跳過驗證與權限，還寫入不存在的欄位 `projectLabel` | 專案卡改走 `fillDraft`（合法選項比對、版本、稽核）；卡片綁定草稿版本 | `block-actions.ts`、`actions.ts`、`tools.ts` |
| 「缺欄位問題」卡片只顯示文字，無法填 | 新增 `field_form` 卡片：日期時間、人員（下拉）、選項、專案搜尋、文字；由後端依表單規格產生，送出走 `fillDraft` | `blocks.ts`、`block-actions.ts`、`message-blocks.tsx`、工具 `propose_field_form` |
| 沒有「修改差異確認」 | 新增 `change_confirm` 卡片：後端以 `planFill` 試算（不寫 DB）列出原值→新值，確認才寫入；過期卡片不寫 | 同上、工具 `propose_draft_changes` |
| 「建立單據」只把一段文字放進輸入框 | 改為直接出「表單類型」卡片（可填表單清單來自權限查詢）；選擇後建立草稿並附上關鍵欄位卡片，全程可只靠點選 | `actions.ts` `presentFormChoicesAction`、`ai-chat-app.tsx` |
| 一般選項卡點了沒有後續 | 非表單選項的點選，等同使用者送出該文字（與打字等價） | `actions.ts`、`message-blocks.tsx` |
| **沒有專案存取權限模型**（第 0 階段 C10） | 新增 `projects.restricted`＋`project_members`；限制專案只有成員能搜尋、出現在選項、由助手或卡片寫入，**正式送出服務也檢查** | `drizzle/0034_project_access.sql`、`src/lib/projects/access.ts`、`projects.ts`、`custom-forms/queries.ts`、`custom-forms/service.ts` |
| 正式送出沒有明確確認 | 「送出單據」先顯示確認框（表單名稱與主要欄位，人員／專案顯示名稱），按「確認送出」才送；「返回修改」不寫任何資料 | `draft-panel.tsx` |
| **手機寬度聊天區寬度為 0**（訊息與輸入框看不見）、文件區超出畫面 | 文件區寬度只在桌面寬度套用，手機上兩區各自全寬 | `ai-chat-app.tsx` |
| 送出後聊天區不會捲到最新訊息 | 新訊息出現時自動捲到底 | `ai-chat-app.tsx` |
| 模型失敗時重新整理只看到使用者訊息，沒有說明 | 失敗回合寫入一則系統說明（「這則訊息沒有處理完成…草稿沒有變更」） | `turn.ts` |
| 草稿庫無法分辨同類草稿 | 草稿庫顯示日期、地點、事由摘要與更新時間 | `draft-work.ts` `summarizeDrafts`、`draft-library-panel.tsx` |
| 卡片訊息顯示內部 ID | 使用者訊息與確認框都顯示名稱 | `block-actions.ts`、`draft-panel.tsx`、`draft-fill.ts` |

**Migration**：`0034_project_access`（`projects.restricted` 預設 false，既有專案行為不變；新表 `project_members`）。**業務規則待你確認**：「限制專案只限成員使用」是我依規格「A 無權使用的專案」建立的最小模型；管理介面（設定哪些專案受限、誰是成員）尚未做，目前只能由資料庫設定。
