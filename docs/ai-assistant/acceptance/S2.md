## 1. 修改摘要

| 根因（實測重現） | 修正 | 檔案 |
|---|---|---|
| AI 更新草稿時，右側面板直接重載，**覆蓋使用者未儲存的手動修改** | 面板有未儲存修改時不套用遠端更新，改顯示「助手已更新到 vN（欄位…），畫面沒有自動套用」；儲存時以載入時的資料為基準：不同欄位自動合併，同一欄位兩邊都改則列出雙方的值，由使用者選擇保留哪一邊 | `draft-panel.tsx`、`draft-work.ts` `saveDraftFromPanel` |
| 手動儲存不經驗證 | 手動儲存與 AI 寫入使用同一個驗證器（必填放寬）與版本控制 | `draft-work.ts`、`actions.ts` `saveDraftAction` |
| 草稿只能在建立它的對話修改 | 新增 `ai_conversation_draft_links`：同一擁有者的對話可經授權綁定舊草稿（只限未送出的草稿，綁定會寫稽核）；修改／附加的權限改為「擁有者，且草稿屬於或已綁定到本對話」 | `drizzle/0033_…`、`schema.ts`、`drafts.ts`、`tools.ts`、`attach-staged.ts` |
| 輸入框上方的「AI 目標草稿」沒有送給後端 | 每回合送出畫面上開啟的草稿（`targetDraftId`）；後端檢查擁有者後綁定，並在工作狀態中列為第一張 | `ai-chat-app.tsx`、`turn.ts`、`draft-work.ts` |
| 儲存遇到網路錯誤時停在「儲存中」，按鈕無法再按 | 捕捉錯誤：顯示「連線中斷，尚未儲存。您的輸入仍保留…」，按鈕可再按；成功時顯示「已儲存 vN · 時間」 | `draft-panel.tsx`、`custom-form.tsx`（`saveNote`） |
| 連點「送出單據」時每次點擊都先存一次草稿 | 送出加單一執行鎖 | `draft-panel.tsx` |
| 正式單據已建立、但後續步驟（複製附件等）出錯時，草稿仍顯示可編輯 | 建立正式單據後先把草稿標為已送出，再複製附件 | `drafts.ts` `submitApplicationDraft` |
| 空白值（`null` 與 `''`）被當成變更；沒有變更也遞增版本 | 空白值視為相同；沒有變更時不寫入，也不遞增版本 | `draft-work.ts` |
| 草稿操作沒有稽核紀錄 | `ai_draft.created`、`ai_draft.updated`（標示 by assistant／panel、版本、欄位、合併欄位）、`ai_draft.linked` | `draft-work.ts`、`drafts.ts` |

**Migration**：`0033_ai_conversation_draft_links`（新表；journal `when` 依專案慣例設為遞增值 1793800000000）。已套用到測試 DB。

## 2. 測試結果

| # | 案例 | 結果 | 方法與證據 |
|---|---|---|---|
| 1 | 重新整理後內容一致 | **通過** | 瀏覽器：草稿 v4（結束 20:00、地點台中市南屯區）重新整理後相同，且與 DB 一致 |

| 3 | 重啟應用程式服務後草稿仍在 | **通過** | 停止並重啟測試站後，畫面仍為 v4，資料相同 |
| 4 | 新對話開啟舊草稿並更新 | **通過** | 真實 Gemini：新對話的回合帶 `targetDraftId`「結束時間改晚上七點」→ 綁定並寫 `ai_draft.linked` 稽核 → 同一草稿 ID 更新到 v2，新對話沒有另建草稿 |
| 5 | 「另外開一張同類申請」產生不同 ID | **通過** | 真實 Gemini：「另外開一張同類的公出申請：11 月 6 日到新竹…」→ 新草稿 ID 不同，原草稿 v1 資料不變 |

| 7 | 關閉文件頁籤不刪除草稿 | **通過** | 瀏覽器：關閉兩個草稿頁籤後，DB 所有草稿狀態仍為 draft（36 張），沒有 abandon 稽核 |

## 3. 剩餘問題

| 問題 | 影響 | 下一步 |
|---|---|---|
| 草稿庫中多張草稿資料相同時無法分辨（實測時有兩張同內容的 v4） | 可能開錯草稿 | 第 3 階段 |
| 先前一次腳本執行（修正前）在建立正式單據 BT0052 後中斷，該測試草稿仍是 draft 狀態 | 只影響測試資料；修正後的程式會先標記草稿 | 若再次送出，會依冪等鍵重播同一張單 |
| 模型不可用時，使用者訊息已存入對話，但重新整理後看不到失敗說明 | 使用者不知道上一句沒有被處理 | 第 3 階段：失敗回合要存一則系統說明 |
| 斷線時，背景輪詢會在主控台產生未處理的 `Failed to fetch` | 開發模式會出現錯誤標記；不影響資料 | 第 7 階段處理輪詢時一併修正 |
| 草稿庫每張卡片只顯示表單名稱與版本，無法分辨是哪一趟 | 選錯草稿的風險 | 第 3 階段加上日期、地點、事由摘要 |
| 修改的草稿可能屬於別的對話，右側可能同時開著好幾張同名頁籤 | 容易混淆 | 第 3 階段處理頁籤標題 |
