## 1. 完整流程（瀏覽器，測試站）

固定句子「找出我已核准的台中公出申請，讓我選一張加入新的差旅報支單。」→ 真實 Gemini 回兩張候選（以日期、地點、事由區分，非單號）→ 選 BT0001 → 夾帶核准 PDF → 一次性帶入卡（出差日期、事由、單號）確認 → 自然語言補其餘欄位 → 預算以選項卡確認 → 上傳多頁 PDF 與發票照片 → 確認並檢查後加入 → 送出 `20261030TR0001` → 簽核者 C 站內預覽 → C、D 核准。

## 3. 本階段修正的問題

| 問題 | 影響 | 修正 |
|---|---|---|
| **核准 PDF 實際渲染是亂碼**：`subset: true` 配 fontkit 會掉字，文字抽取卻完全正常 | **本階段第一版報告曾依文字抽取判定通過，是假通過。** 第 8 階段走旅程時由畫面發現 | 不再子集化：改全量嵌入 4 MB 常用字型（保留 GID），缺字才用完整字型。驗收改看實際渲染 |
| PDF 欄位是英文內部代碼、值是 JSON、狀態是 `approved` | 簽核者看不懂；預算、專案只有 UUID | 依表單定義輸出中文標籤與顯示值，表格逐列列出，敏感欄位遮罩 |
| 必附件表單的附件都在草稿上時，送出被擋「請上傳附件」 | **所有靠對話夾帶附件的必附件表單都送不出去** | `submitApplicationDraft` 把草稿附件數計入檢查 |
| 開第 2 個以後的附件，檢視器先載第 1 個：舊圖片蓋在 PDF 上、PDF 畫布空白 | **簽核者會看到錯的檔案** | 載入加序號，只有最新一次可更新畫面 |
| 快速翻頁或縮放時對同一畫布同時渲染 | 出現渲染失敗 | 新渲染前取消舊工作 |
| 圖片旋轉後移出可視範圍 | 90／180／270 度看不到圖 | 依角度補位移 |
| 檢視器標題被工具列擠成一個字 | 看不出檔名 | 標題獨立一行 |
| Office 轉換失敗後永遠顯示「轉換中」 | 假狀態 | 有失敗紀錄就回報失敗 |
| Office 檔被送給模型而得到 400 | 白費一次外部呼叫、錯誤訊息誤導 | 只把圖片與 PDF 送模型，其餘明說不做檢查 |
| 錯誤訊息曾直接顯示英文例外 | 使用者看不懂 | 改為可操作的中文訊息 |

## 5. 剩餘問題

| 項目 | 影響 | 下一步 |
|---|---|---|
| Office 真實轉換 | 上線環境若要宣稱 Office 可預覽，需安裝 LibreOffice 並重驗案例 7 | 第 8 階段列於未驗證 |

| 送出後複製附件時若伺服器當機，重送走重播路徑，不會補複製 | 草稿檔案仍在，但單據可能少附件；部分失敗有 `copyFailures` 回報，當機則否 | 列為後續改善 |
| 核准動作無二次確認 | 既有行為，按「核准」即執行 | 由使用者體驗確認決定 |
| 字型以外部工具裁出，存於 `assets/fonts/NotoSansTC-Common.otf` | 需一併提交；更換時必須再看渲染結果 | 步驟見 `assets/fonts/README.md` |
| 已存在的舊版快照（`accsys-approved-pdf-v1`）不會自動重產 | 若上線前已有快照，內容仍是亂碼。快照依版本與輪次去重，新版字型不會取代 | 測試環境已清除；正式環境尚未部署此功能，上線前確認沒有 v1 列 |
