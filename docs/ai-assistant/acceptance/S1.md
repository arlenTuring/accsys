## 1. 修改摘要（對應第 0 階段根因）

| 根因 | 修正 | 檔案 |
|---|---|---|
| C1 值不驗證就存入 | 新增確定性填單層：日期時間正規化為台北牆鐘 `YYYY-MM-DDTHH:mm`（含時區位移者換算）、金額／數字／選項（可用選項文字）／是否；參照欄位（人員、專案…）在**表單合法選項**中比對，只有唯一精確且無其他相近者才採用，否則回傳 `ambiguous`／`not_found` 與候選；再以**正式送出用的同一驗證器**（必填放寬）檢查，不合法的變更退回原值並回報，合法的照存 | `src/lib/ai-chat/draft-fill.ts`（新） |
| C2 假成功 | 每次寫入回傳 `saved`（DB 實際存入值）、`rejected`（原因＋候選）、`missing`（同驗證器算出的缺漏必填）、最新 `version`；聊天中加一則**後端產生的收據**（`action_result`，非模型文字）；模型回覆規則改為只依 saved／rejected 敘述 | `tools.ts`、`vertex-client.ts` |
| C3 公出單無專案欄位 | 公出差旅申請單新增選填「關聯專案」（`projectId`，type project，semantic project，送出時寫入單據 `project_id`） | `src/lib/custom-forms/migrated/business-trip.ts` |
| C4 回合預算耗盡 | 「建立」與「填入」合併為一個工具（`create_application_draft` 帶 `set`／`rows`）；修改用 `update_application_draft`；新增 `get_form_spec`。一般建單 2 回合完成、修改 1 回合完成；**未調高回合上限** | `tools.ts` |
| C5 不知道今天 | 每回合注入日曆：今天、星期、本週與下週日期列、公司時區 | `draft-work.ts` `calendarContext` |
| C6 只有文字歷史 | 每回合注入**權威工作狀態**（由 DB 產生）：本對話草稿 id、version、已填值、明細 row_id、尚缺必填、目前草稿的完整欄位規格；不存成使用者訊息 | `draft-work.ts` `buildWorkState`、`turn.ts` |
| C7 建立時重用他單 | 移除「同表單就重用」；建立一律新建，以「回合 ID＋表單＋內容摘要」作冪等鍵（同一回合重送不重複） | `tools.ts` |
| C8 內部提示外洩 | 備援文字只用後端收據或固定說明「這次沒有完成任何草稿變更」 | `vertex-client.ts` |
| P3 明細整欄覆寫 | 明細列以穩定 `_rid` 逐列 `add`／`update`／`delete`；舊列無 ID 時可用 `#n`；合計與公式由後端驗證器計算 | `draft-fill.ts` |
| 參數二次序列化 | `patch_json` 字串改為結構化陣列參數（`set`、`clear`、`rows`） | `tools.ts` |
| 無 schema 可寫任意鍵 | 載不到表單規格即拒絕；未知欄位一律 `unknown_field` | `draft-fill.ts`、`draft-work.ts` |
| A8 故障注入 | 非 production 才生效：回合選項 `fill.failWrite` 或環境變數 `AI_FAULT_INJECT=draft_write`；失敗時不寫 DB、版本不變 | `draft-work.ts` |
